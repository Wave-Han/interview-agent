# Phase 3(Eval 黄金集 + 生成器-评估器)实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `eval` 子命令跑 20 题 × 3 档黄金集,产出档位命中率报告(真跑落 docs);生成器-评估器上下文隔离;清完 P2 遗留 4 项。

**Architecture:** 判题 rubric 消息构造从 quiz 抽为共享函数(零行为变化);eval 用同一 run_agent 循环但工具面仅含指向 EvalRecorder 的 record_result(不落学习库);黄金集答案由 scripts 生成器(无 rubric 视野)生成、执行者持 rubric 校对定稿。

**Tech Stack:** Python 3.13、httpx、sqlite3、pytest。零新增依赖。

**Spec:** `docs/superpowers/specs/2026-10-27-phase3-eval-design.md`

## Global Constraints

- 依赖白名单不变(httpx、python-dotenv、redis 可选、pytest);零新增。
- quiz/ask/index 行为零变化:现有 45 测试必须原样通过。
- eval 不写 attempts/wrong_notes(存储隔离是本阶段核心不变量)。
- 注释英文;用户可见输出中文;`.env` 不入库。
- 每 Task:pytest 全绿 + commit;涉及真实 LLM 行为的交付物必须真跑。

## Review Focus

1. **eval case 模型未调 record_result** → 记 `no_record`,不崩不挂死(安全阀兜住)(Task 3 测试)。
2. **golden 含不存在 question_id** → 启动即中文报错退出,不静默跳过(Task 3 测试)。
3. **eval 全程零 DB 写入 attempts** → 核心隔离断言(Task 3 测试)。
4. **embed 65 条输入** → 恰好 2 次 HTTP 请求、结果保序拼接(Task 2 测试)。
5. **eval --sample 可复现** → 同 seed 两次运行抽中同一批 case(Task 4 测试)。
